# Решения и отклонения от workflow

Формат записи: `Шаг N: <решение> — <причина>`.

Шаг 1: `LogFile.Path` хранит абсолютный путь (`FileStream.Name`), а не строку, переданную в `Open` — свойство всегда отдаёт однозначный полный путь к открытому файлу.
Шаг 1: `LogFile.Length` запрашивает `RandomAccess.GetLength` при каждом обращении, а не кэширует значение — файл может расти, и будущий tail должен видеть актуальный размер.
Шаг 1: `LogFile.Read` циклически вызывает `RandomAccess.Read`, пока буфер не заполнен или не достигнут EOF — контракт «до заполнения или EOF» не зависит от того, вернул ли один вызов меньше запрошенного.
Шаг 1: тестовые проекты используют xunit 2.x; файлы тестов создаются во временной папке с уникальным именем и удаляются в `Dispose` тестового класса.
Шаг 2: `IndexSnapshot` хранит ссылки на таблицы чанков (`long[][]` и `byte[][]`) и создаётся только в `Publish`; таблица писателя растёт через `Array.Resize`, т.е. копированием ссылок, поэтому ранее опубликованные снимки остаются валидными без блокировок.
Шаг 2: `RaiseLastLevel` пишет уровень через `Volatile.Write`, чтобы повышение уровня было видимо читателям без отдельного изменения `Count`; окончательная публикация всё равно происходит через `Publish`.
Шаг 2: `End` вне диапазона также бросает `ArgumentOutOfRangeException`, как `Offset` и `Level` — единообразная проверка индекса.
Шаг 2: чанк выделяется целиком при первом обращении к нему (589 824 байта: `long[65536]` + `byte[65536]`), что соответствует бюджету 9 байт/запись.
Шаг 3: BOM проверяется отдельным чтением 3 байт при пустом индексе; смещения записей начинаются с 3, но `IndexedLength` остаётся 0, пока не встретится первый `\n`.
Шаг 3: незавершённая строка переносится в начало буфера и перечитывается вместе со следующим блоком; буфер растёт только когда заполнен и не содержит `\n`.
Шаг 3: прогресс считается по байтам до последнего полного `\n` (а не по прочитанным вперёд байтам), в конце принудительно сообщается 100.
Шаг 3: первая строка файла без timestamp создаёт запись `Other` и не проверяется дополнительно на `Exception` — правило 4 имеет приоритет над повышением уровня продолжения.
Шаг 3: несоответствие `start` значению `IndexedLength` — `ArgumentException`; отрицательные значения и `end < start` — `ArgumentOutOfRangeException`.
Шаг 3: при поиске первого токена для `IsExceptionContinuation` токен ограничивается пробелом, табуляцией или `:`, поэтому `NullReferenceException:` и `System.ArgumentException:` распознаются как продолжение исключения.
Шаг 4: исключения выбираются как подмножество ~5% записей с уровнем ERR (20% из них), чтобы не нарушать распределение ~85/10/5; при индексации такие записи повышаются до Exception из-за стектрейса.
Шаг 4: для полной воспроизводимости используется собственный SplitMix64 вместо `System.Random` — реализация `System.Random` может меняться между версиями .NET.
Шаг 4: генерация вынесена в публичный `LogGen.LogGenerator.Generate`; тесты ссылаются на проект `tools/LogGen`, а CLI вызывает тот же метод.
Шаг 4: BOM при `--bom` пишется напрямую в поток до создания `StreamWriter` с UTF-8 без BOM, чтобы BOM присутствовал даже при `--count 0`.
Шаг 5: `LogSession.IndexAsync` запускает индексацию через `Task.Run` с внутренним `CancellationTokenSource`, связанным с переданным токеном; параллельный запуск запрещён (`InvalidOperationException`), после завершения можно продолжить с `IndexedLength`.
Шаг 5: `LogSession.Dispose` отменяет задачу, дожидается её и проглатывает любые исключения индексации, чтобы закрытие приложения не падало; файл освобождается только после завершения задачи.
Шаг 5: `IndexTime` измеряется `Stopwatch` и хранится в тиках через `Interlocked`, чтобы UI мог безопасно читать его после `await`.
Шаг 5: в UI используется `Progress<int>` (обновление прогресс-бара в UI-потоке) и `System.Windows.Forms.Timer` с интервалом 200 мс для `VirtualListSize`; список показывает только заглушки `entry N [level]`.

# Smoke test и общие соглашения (не относится к конкретному шагу)

Smoke test: `tests/LogViewer.Tests/PlayerLogTests.cs` индексирует `samples/Player.log` и проверяет инварианты (`Other < 2%`, `End(i) > Offset(i)`, `End(last) == IndexedLength`, `IndexedLength == File.Length`). Это НЕ часть workflow шагов 1–10, а защита от регрессии индексатора. При выполнении шагов 4+:
- не изменять `samples/Player.log`;
- не удалять, не переименовывать и не «улучшать» `PlayerLogTests.cs`;
- не использовать `samples/Player.log` как цель для `LogGen generate` (использовать отдельный путь в `samples/` или временную папку);
- если тест упал — сообщить в отчёте, не пытаться «исправить» его самостоятельно.
